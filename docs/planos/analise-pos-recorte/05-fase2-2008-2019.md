# 05 — Fase 2: quando ocorreu o desmate na AUAS (2008 → 2019)

Botão **"Continuar: quando ocorreu o desmate (2008–2019)"**, liberado só depois da
Fase 1 concluída.

## 1. Pergunta que a fase responde

Para **cada polígono AUAS**: em que **ano** a vegetação nativa virou uso antrópico, ou
em que **intervalo fechado**, dentro da janela pós-marco até 2019?

Não é conclusão jurídica: é evidência visual de conversão, com fonte, anos comparados,
confiança e limitações.

## 2. Por que a janela termina em 2019

De 2019 em diante existe dado **melhor e datado**: os alertas SCCON já usados pela aba
AUAS × SCCON gravam `ABERTURA` com a data do alerta (ver [`docs/AUAS_SCCON.md`](../../AUAS_SCCON.md)).
Interpretar mosaico anual onde existe alerta datado seria piorar o dado. O relatório da
Fase 2 termina com um encaminhamento explícito:

> Para eventos a partir de 2019, use a aba **AUAS × SCCON** — a datação vem do alerta
> oficial, não de interpretação de imagem.

Se o polígono ficar `SEM_MUDANCA_OBSERVADA` até 2019, o texto deve sugerir esse
próximo passo em vez de afirmar que não houve desmate.

## 3. Série e âncora

- **Âncora (não conta como mudança):** SPOT 2008 da Fase 1, reaproveitado como
  referência visual. Opcionalmente `Mosaicos:LANDSAT_5_2008` como cena de calibração
  do mesmo ano em outro sensor (decisão A1).
- **Série analisada:** 2009 → 2019, exatamente os anos que o catálogo em runtime
  habilitar (doc 03). Ano reprovado no `GetMap` sai da série e vira limitação.

## 4. Janelas de visão

Padrão proposto — 5 janelas por polígono, com **ano compartilhado** entre janelas
vizinhas para não depender de memória entre requisições:

| Janela | Anos | Observação |
|---|---|---|
| `W2009_2011` | 2009, 2010, 2011 | tudo Landsat 5 |
| `W2011_2013` | 2011, 2012, 2013 | cruza L5 → ResourceSat → L8 |
| `W2013_2015` | 2013, 2014, 2015 | tudo Landsat 8 |
| `W2015_2017` | 2015, 2016, 2017 | L8 (ver escolha de candidato, doc 03 §4) |
| `W2017_2019` | 2017, 2018, 2019 | cruza L8 → Sentinel-2 |

**Janela-ponte (condicional).** Se o redutor apontar a transição exatamente numa
fronteira de sensor (2011/2012, 2012/2013 ou 2017/2018), disparar **uma** janela extra
com o par de anos em torno da fronteira usando o candidato alternativo do catálogo
(ex.: `SENTINEL_2_2016`+`SENTINEL_2_2017` em vez de Landsat 8). Se a ponte confirmar →
mantém ano confirmado; se divergir → rebaixa para intervalo. Se não houver alternativa
publicada → rebaixa para intervalo e registra a limitação.

Custo: 5 janelas × ~5,5k tokens ≈ 27k tokens por polígono → com 8k TPM, **~4 a 6
minutos por polígono**. A prévia da UI (doc 07) precisa mostrar isso antes do clique.

## 5. O que a visão devolve (JSON estrito)

Por cena, o mesmo vocabulário da Fase 1 — reuso, não dialeto novo:

```
state: NATIVE_VEGETATION | ANTHROPIZED | MIXED | NOT_OBSERVABLE
observableFraction: 0..1 | null
confidence: HIGH | MEDIUM | LOW | INCONCLUSIVE
evidence[]: frases curtas do que foi visto
limitations[]: nuvem, borda, resolução…
```

Mais, por par consecutivo dentro da janela: `transition: NONE | NATIVE_TO_ANTHROPIZED |
ANTHROPIZED_TO_NATIVE | UNCLEAR` (regeneração existe e não pode ser silenciada).

O modelo **não** recebe termo jurídico, **não** vê o resultado da Fase 1 e **não**
escolhe o ano final.

## 6. Redutor determinístico (o veredito)

Ordena apenas cenas `USABLE` e aplica, nesta ordem:

```text
1. ANTHROPIZED na primeira cena utilizável da série (2009 normalmente)
   → JA_ANTROPIZADO_NO_INICIO_DA_SERIE
     (e, se a Fase 1 deu ALERTA_PRE_2008 nesse polígono, o texto diz que é
      coerente com evento anterior ao marco — sem recalcular a Fase 1)

2. NATIVE em Y-1 (utilizável) + ANTHROPIZED em Y (utilizável),
   com as janelas que contêm Y-1 e Y concordando
   → CONFIRMADO_ANO, firstDetectedYear = Y
     • se Y-1→Y cruza troca de sensor: exige janela-ponte confirmando,
       senão vira CONFIRMADO_INTERVALO [Y-1, Y]

3. NATIVE em A + ANTHROPIZED em B, com B > A+1 (anos intermediários não utilizáveis)
   → CONFIRMADO_INTERVALO, observedInterval = [A, B]

4. Nenhuma transição em toda a série exigida e utilizável
   → SEM_MUDANCA_OBSERVADA  (+ encaminhamento para AUAS × SCCON)

5. Qualquer lacuna crítica, conflito entre janelas ou cena não observável
   que impeça 1–4
   → INCONCLUSIVO
```

Regras duras:

- **Ano exato só com dois anos consecutivos utilizáveis.** Sem isso, intervalo.
  > ⚠️ A implementação **violava esta regra** até 2026-08-07: exigia os dois anos
  > utilizáveis e concordantes, mas não que fossem consecutivos — uma transição
  > 2010→2015 virava "CONFIRMADO_ANO 2015". Como a regra do ano exato capturava esse
  > caso, a regra do intervalo só era alcançada quando os extremos **não** eram
  > observáveis, ou seja, as duas estavam invertidas na prática. Corrigido em `ad5ae786`
  > com teste de regressão (`pos2008/evidence-reducer.test.ts`).
- Duas janelas que discordam sobre o mesmo ano compartilhado → aquele ano vira
  `NOT_OBSERVABLE` para efeito de decisão e a limitação é registrada.
- `MIXED` nunca sozinho fecha transição; precisa de `ANTHROPIZED` em ano posterior.
- Uma transição `ANTHROPIZED_TO_NATIVE` isolada (regeneração) não zera uma conversão
  anterior — os dois eventos são registrados.

## 7. Agregado do imóvel

```
polígonos com ano confirmado   → contagem + área (ha) + histograma por ano
polígonos com intervalo        → contagem + área
já antropizados no início      → contagem + área  (cruzar com o alerta pré-2008 da Fase 1)
sem mudança observada          → contagem + área
inconclusivos                  → contagem + área
```

O agregado **nunca** substitui a tabela por polígono, e o "ano do imóvel" não existe:
se o usuário quiser um número, mostra-se o ano mais antigo confirmado, rotulado como tal.

```ts

  | "CONFIRMADO_ANO"
  | "CONFIRMADO_INTERVALO"
  | "JA_ANTROPIZADO_NO_INICIO_DA_SERIE"

  | "INCONCLUSIVO";

type AuasPos2008PolygonResult = {
  polygonId: string;            // idêntico ao da Fase 1
  geometryHash: string;         // idêntico ao da Fase 1

  observedInterval: { fromYear: number; toYear: number } | null;

type AuasPos2008Analysis = {
  schemaVersion: 1;
  rulesVersion: "auas-pos2008-v1";
  phase: "POS_2008";
  jobId: string;

             missingYears: number[]; alternativesAvailable: Record<number, string[]> };
  summary: { polygonCount, confirmedYearCount, intervalCount,
             alreadyAnthropizedCount, noChangeCount, inconclusiveCount,
             totalAuasAreaHa, areaByStatusHa: Record<AuasPos2008Status, number>,

  polygons: AuasPos2008PolygonResult[];

  limitations: string[];
  startedAt: string; completedAt: string;

```

## 9. Rota

```
POST /api/simcar/clip/analyze-auas-pos2008
body: { jobId, contextUrl?, outputZipUrl? }
→ SSE: job_started, progress, billing, report_error, error, complete
→ 409 { code: "PHASE_NOT_READY", requires: "PRE_2008" } se a Fase 1 não concluiu
→ 409 { code: "PHASE1_MISMATCH" } se algum geometryHash divergir
```

Entra na allowlist de `backend/app.ts`. Progresso em SSE:
`{ step, percent, message, polygonIndex, polygonTotal, windowIndex, windowTotal, etaSeconds }`
— mesmo formato de `AuasV2Progress`, para o front reaproveitar o componente de barra.
